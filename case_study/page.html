The setup

A real research program, messy the way real data is

Five studies from five labs, published between 2006 and 2019: 265 samples, 8 breast cancer cell lines, 10 compounds, two microarray platforms and two RNA-seq pipelines. All are public in NCBI GEO, so anyone can download the same files and repeat the test.

I wrote 25 questions a biotech team asks about its data, like sample counts, doses, controls and gene changes. I answered each one by query, then checked every answer by hand against the raw files and the papers. That became the answer key, and a grading script scores each AI answer automatically.

Two models, claude-opus-5-5 (Anthropic) and gpt-6-astra (OpenAI), each answered every question three times on the raw files and three times on the clean database. Instructions, tools and time limits were identical in both conditions. See the test harness.

Scored on 23 of the 25 questions. Two were dropped after the run as ambiguous (Q10's answer key was too strict; Q23 had a defensible second reading). All 300 answers, including those two, are in the table at the bottom.

What was wrong with the files

75 problems, each written down with evidence and a fix

28 would give a wrong answer if missed, 21 give a plausible but misleading one, and 26 slow people down. The clean database handles all 75: 63 fixed by a written rule, 12 flagged for the analyst, 0 left uncovered. These are the strongest examples. Download the full inventory (CSV).

The clean database

One table per real thing, traceable to the raw file

One official ID per gene, compound, cell line and sample. The raw files are never edited; checksums prove it on every build, and one command rebuilds the whole database from them.
